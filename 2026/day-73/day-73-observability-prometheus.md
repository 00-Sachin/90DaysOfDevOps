# Day 73 — Observability and Prometheus

## 1. Three Pillars of Observability

### Metrics

Metrics are numerical measurements collected over time. They help us understand the health and performance of a system, such as CPU usage, memory usage, request count, and error rate.

### Logs

Logs are timestamped records of events generated by applications and systems. They are useful for understanding what happened when an error or unexpected event occurs.


### Traces

Traces show the journey of a single request through different services or components of an application. They help identify where a request is delayed or where a failure occurs.


### Why All Three Are Needed

- **Metrics** tell us what is happening.
- **Logs** help explain why it happened.
- **Traces** help identify where it happened.

**Query:**

---

### Query 3 — Total HTTP Requests

**Purpose:** Check the total number of HTTP requests received by the Prometheus server.

**Query:**

prometheus_http_requests_total


---

### Query 4 — HTTP Requests by Handler

**Purpose:** Examine HTTP requests for a specific Prometheus handler.

**Query:**

prometheus_http_requests_total{handler="/targets"}

---

### Query 5 — Non-200 HTTP Request Rate

**Purpose:** Find the per-second rate of non-200 HTTP requests over the last five minutes.

**Query:**

sum(rate(prometheus_http_requests_total{code!~"2..|3.."}[5m]))

## 6. Counter vs Gauge

### Counter

A counter is a metric that only increases, except when it is reset. It is useful for measuring cumulative events.

**Real-world example:** Total number of HTTP requests handled by a server.

### Gauge

A gauge represents a value that can increase or decrease over time.

**Real-world example:** Current memory usage of a server.

### Difference

| Counter | Gauge |
|---|---|
| Normally only increases | Can increase or decrease |
| Used for cumulative events | Used for current state or value |
| Example: total requests | Example: current memory usage |
